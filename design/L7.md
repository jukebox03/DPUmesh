# DPUmesh L7 Layer

DPUmesh moves bytes; an L7 layer decides where they go. The two meet at one
C ABI, `linkerd/include/dmesh_l7.h`, and share nothing else: DOCA devices,
progress engines, DMA rings and connection state stay with the datapath.

The layer is a build-time choice. `-Dl7_backend=null` compiles the reference
consumer in `linkerd/shim/`; `-Dl7_backend=linkerd` links a Rust staticlib
carrying linkerd2-proxy. Neither changes a line of `doca/`.

## 1. Modes

One data plane carries every mode: payload lands in pod staging and leaves by
scatter-gather DMA. What differs is how far the L7 layer is involved, chosen per
service.

| Mode | The L7 layer contributes | Payload traverses it |
|---|---|---|
| `decision` | authorization, discovery, endpoint choice, identity, telemetry | no |
| `opaque` | the above, over a byte stream it may encrypt | yes |
| `l7` | the above, plus request-level routing | yes |

```text
DPUMESH_L7_DECISION_SVC=<service ids>
DPUMESH_L7_OPAQUE_SVC=<service ids>
DPUMESH_L7_SVC=<service ids>
```

A service named by no list is forwarded by the data plane alone. A service named
twice is rejected at startup. With every list empty the layer is not attached and
the egress arena is not allocated, so the execution path is the transport's own.

`decision` exists because policy is a per-connection question and encryption is
not. Asked once at establishment, the layer answers allow-or-deny and an
endpoint; the payload then takes the zero-copy path and the layer costs nothing
per byte. A sidecar cannot offer this: its bytes must traverse a userspace hop
to reach the same decision.

When the layer declines a connection, or is not attached, the data plane
forwards it at L4 without policy. That is an availability fallback, not a
selectable mode, and it is counted.

## 2. Thread model

`A` ARM workers each own a connection table, conntrack, SG-DMA engine and
progress engine, reached through `__thread px_cur_worker`. Nothing is shared and
no lock is taken between them.

The L7 layer therefore runs one instance per worker, on that worker's thread. A
work-stealing runtime is excluded: a task moved across threads would touch
another worker's state.

The worker loop owns the iteration. It advances the layer once per revolution
and folds the result into the progress test that governs arming, parking and the
1 ms backstop:

```text
did = dpu_progress_worker_pe(...)
run = dpu_worker_run(...)          includes l7_worker_step()
if did or run: continue
arm → recheck → epoll_wait(1 ms)
```

The layer exposes a single step rather than owning a loop, and arms no timer of
its own.

## 3. Data path

### Arrival

`px_parse_linkerd` hands the window's staging extents to the layer by pointer
and does not consume them. `l7_handed` tracks how far the hand-over has reached;
`parse_pos` stays behind it, so custody outlives the parse pass. The layer
returns custody with `dmesh_l7_release`, which advances `parse_pos`, frees the
arrival and acknowledges the sender's slot.

Releases are applied at the end of the pass, never inside it: `px_advance`
unlinks fully-consumed arrivals, and the walk is still holding them.
`px_worker_state.in_l7_parse` distinguishes the two cases, and a release
reported outside a pass parks the connection so one is scheduled.

Two bounds keep a slow consumer from monopolising the transport:
`PX_L7_CUSTODY_MAX` caps the bytes one connection may hold unreleased, and
`PX_L7_SEGMENTS_PER_PASS` caps hand-overs per pass. What is left re-enters
through the stall list.

### Egress

Bytes the layer produces are not in any pod's staging, so the engine sources
them from a DPU-local arena instead. `px_piece` carries either an arrival
extent, with custody attached, or an arena chunk; one scatter-gather list may
hold both.

```text
struct px_piece
  arr   != NULL  →  pod staging, custody counted
  chunk != NULL  →  egress arena, returned with the unit
```

Chunks return in `px_unit_free_node` and nowhere else. Every unit passes through
it — delivered, dropped, or abandoned before submit — which makes a leak on an
error path structurally impossible.

The layer reaches the arena two ways. `dmesh_l7_tx_reserve` lends it DMA-able
memory to encode into directly, so the bytes are never copied again;
`dmesh_l7_send` copies a whole message in and chains as many chunks as it needs
so the message is delivered whole.

### Lifecycle

| Datapath event | L7 layer |
|---|---|
| first arrival on a connection | `l7_conn_open` |
| window extent available | `l7_conn_segment` |
| peer half-close | `l7_conn_eof` |
| teardown, poisoning, slot reuse | `l7_conn_close` |

A connection closes before its window is dropped, so the layer never holds a
pointer into reclaimed staging. FIN is deferred while the layer still owes
releases: an unconsumed tail there is payload in flight, not truncation.

## 4. Backend selection

The layer names the backend. `dmesh_l7_backends` lists a service's live
candidates; both publishing calls take the chosen pod, and
`DMESH_L7_BACKEND_ANY` returns the choice to the data plane's balancer. The
reply direction is routed by conntrack and ignores the argument.

Granularity is the layer's to choose, and it is what the cost is made of. Each
delivery is one host-side publication, so routing per message means one delivery
per message; pinning a connection lets consecutive messages share one.

Per-message routing also reorders responses on a protocol that matches them
positionally. It is correct only where responses carry their own correlation, as
HTTP/2 stream identifiers do.

## 5. Identity

The layer needs to know who is calling. `POD_IDENTITY` carries a workload name
on the registration connection before `POD_REGISTER`, and the DPU binds it to
the slot that connection owns, clearing it when the slot takes a new tenant.

Identity is therefore granted, not claimed: a pod cannot name itself as another
workload, because the binding is to the comch connection and the registered
memory region. A pure client sends none and reaches the layer with an empty
workload.

`dmesh_l7_flow` carries this alongside the routing keys, the connection's mode
and its direction, so one layer serves every mode without a second channel
telling it which is in force. `peer_pod` names the other end of the session,
which is what lets the layer recognise a reply as belonging to a connection it
already opened.

## 6. Security

Within a node, bytes travel `pod memory → PCIe → DPU memory`. No cable and no
network stack, so the eavesdropping and interposition threats that mTLS answers
do not apply, and traffic is carried in plaintext. Between nodes it is
terminated on the DPU.

The guarantee is not proximity. It is that the DPU enforces per-pod memory
isolation and routing, which holds under multi-tenancy exactly as it does
without it. Because the payload stays as the sender wrote it, the arrival extent
can also be a scatter-gather source for the departure — which encryption would
forbid, since ciphertext is new bytes.

## 7. Consumers

`linkerd/shim/l7_null.c` implements the contract with no protocol of its own:
opaque streams pass through, framed streams are reassembled and routed per
message, and `decision` queries are answered. It exists so the datapath can be
validated, and so what the contract requires is stated twice — once as a header,
once as working code.

`linkerd/rust/` carries linkerd2-proxy. It creates one `current_thread` runtime
per worker, builds the proxy from the environment, and bridges the contract onto
the proxy's own endpoint type. The two directions cross:

```text
client conn ──segments──▶ client endpoint ──proxy reads request
                                                    │
backend endpoint ◀──proxy writes request────────────┘
      │
      └─take_tx──▶ dmesh_l7_send(request conn)  ──▶ backend pod

backend pod ──▶ reply conn ──segments──▶ backend endpoint ──proxy reads response
                                                    │
client endpoint ◀──proxy writes response────────────┘
      │
      └─take_tx──▶ dmesh_l7_send(reply conn)    ──▶ client pod
```

Each endpoint's output leaves on the *other* direction's connection, because
that is the DPUmesh connection whose upstream reaches the intended peer.

The proxy needs a control plane before it will serve; the port ships mock
destination, identity and policy binaries that satisfy it without the DPU
holding cluster credentials.

## 8. Cost

Measured at rates every mode serves, carrying payload through a terminating
layer costs nothing separable from the data plane alone: an opaque stream, a
framed stream, and a connection that only asks one question all land within the
run-to-run spread of the plain path. Routing per message costs about 20% more
per request than routing per connection.

What per-message routing costs is capacity. It stops at roughly 170,000 messages
per second whatever the message size, because a destination that changes between
messages cannot share a delivery with the one before it. That is §4's claim
measured. The figures and the method are in `bench/report/REPORT_L7.md`.

Latency at one outstanding request improves. The data plane sources its
scatter-gather from arrival staging, so the sender's transmit credit returns only
after the destination's DMA completes; copying into the arena frees the staging
at once and the credit returns a round earlier. The reference consumer releases
immediately, so a layer that holds bytes longer sees less of this.

A delivery that spills past a chunk becomes a two-source gather, and a message
whose tail arrives as its own forward completion becomes two deliveries. Both
are visible at sizes that straddle those boundaries.

## 9. Limits

Balancing is per worker. Each instance sees only its share of the connections
and their sequences cannot be shared, so independent balancers converge on the
same backend where the data plane's single counter would spread. A
shared-nothing balancer has to derive its spread from the flow, and even then
covers the backends only in proportion to the connections it sees.

The linkerd consumer is sound for one connection at a time: the port's backend
registry is keyed by address and hands each entry out once. Inbound proxying is
not wired; this covers the outbound direction.
